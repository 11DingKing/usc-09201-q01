# 林地权属版本账领域约定

项目面向集体林权改革与林下产业协作场景，业务记录需要区分来源、发生时间与当前有效版本。涉及个人、机构或敏感地点的信息只应向职责范围内的角色开放，所有对外结果都应能够追溯到采用的数据版本。

## 核心原则

1. **只追加、不覆盖**：每次成员增减、局部流转、边界调整、证照撤回都是一条不可改删的版本记录。SQLite 触发器禁止对 `versions`、`audit_log` 执行 UPDATE/DELETE。
2. **双时间轴**：每条事件同时记录
   - `occurred_at`：业务发生时间（边界实际调整、流转实际开始、成员实际入册的日子）；
   - `recorded_at`：入账时间（经办人提交、复核员通过的时刻）。
   当前权属状态始终按 `occurred_at` 归并，因此**迟到补录落在时间线的历史位置**，旧扫描件无法盖过更新的决定。
3. **版本即冻结快照**：版本号按复核通过顺序单调追加（v1、v2、v3…），每版入账时物化当时完整快照。事后补录只产生新版本，v3 的冻结结论永远不变；当前视图则按全部事件重放，可反映“补录后才发现 v3 漏了某位共有人确认”。
4. **变更先入复核队列**：经办人提交的申请为 `pending`，复核员通过后才生成生效版本。队列持久化，服务重启后未完成复核仍在原队列。
5. **乐观并发**：提交须带 `base_version`。基线过期或同宗地已有待复核修订时，申请以 `conflicted` 状态留档并返回 409；两名经办人并发修订恰好一个生效，另一个可基于新版本重新提交。
6. **角色与脱敏**：
   - `operator`（经办人）：登记、提交变更；
   - `reviewer`（复核员）：审批/驳回、查审计；
   - `registrar`（登记机关）：签发、撤回权证；
   - `institution`（授权机构，如银行）：核验，姓名可见、身份证号与电话按规则脱敏。
7. **完整审计**：提交、冲突、复核、签发、撤回、核验（含阻断结论）全部写入 SHA-256 哈希链，可通过 `/api/v1/audit/chain` 重放校验。

## 核验阻断理由（机器可读码）

| code | 含义 |
| --- | --- |
| `cert_withdrawn` | 证照已被撤回，附撤回时间与理由 |
| `cert_superseded` | 旧证已被新证替代，附新证号 |
| `cert_outdated` | 证载版本落后于当前生效版本但新证未发，旧证不得覆盖新决定 |
| `cert_boundary_stale` | 发证后承包边界已调整，证载边界不是最新决定 |
| `boundary_confirmation_missing` | 边界调整未经全体相关共有人确认（含迟到补录揭示的共有人），附缺失人员 |

核验结果同时返回 `issued_version` 与 `effective_version`，企业和村集体都能据此说明“这张证对应哪一版、现在有效是哪一版”。流转记录附 `scheduled/active/expired/ended_early` 派生状态，用于说明流转期限。
